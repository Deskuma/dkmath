## 2. 現在の実装面の確認

今回の優先順位は、文書の記述だけではなく、現在の公開ソースを基準に決める。

### 2.1 GN / Tail / valuation

既存の実装面は次の通りである。

- `DkMath.CosmicFormula.GTail` に `GTail`、`add_pow_eq_prefix_add_xpow_mul_GTail`、`higher_tail_eq_pow_mul_GTail`、`GTail_rec` がある。
- `DkMath.CosmicFormulaBinom` に legacy `GN` の `GN_eq_sum` と、現在追加された `GN_eq_G` / `G_eq_GN` がある。
- `DkMath.NumberTheory.Gcd.GN` に差冪商、gcd、coprime、padic valuation、squarefree GN からの Body 非完全冪の橋がある。
- `DkMath.NumberTheory.PrimitiveBeam` に primitive prime の GN divisibility、no-lift 版、squarefree GN 版の局所評価がある。

ただし primitive-prime の一般 valuation 経路には `..._research` theorem が残る。そこから無条件の一般 FLT 閉路を新候補として主張しない。

### 2.2 有限 prime world / GN bridge

次の層はすでに利用可能な前提とする。

- `FinitePrimeWorld` / `PeriodicPrimeWorld` / `PrimeWorldResidues`
- `PrimeWorldRefinement` の新方向挿入、唯一の予約 child、`q - 1` 生存 child
- `PHZ30` の `{2,3,5}`、30 周期、210 refinement、48 candidate seats
- `StructuralArithmetic.GNBridge` の primitive prime → `FreshPrimeDirection` と `GN5` compatibility

したがって、Prime Gauge のために同じ有限 sieve や `FreshPrimeDirection` を再定義しない。

### 2.3 独立した実数例

`DkMath.PowerSwap.Branch` と `DkMath.PowerSwap.Contours` はそれぞれ build 可能で、次がすでにある。

- `powerSwap_branch_correct`
- `gapQ_eq_xy_mul_Hdiff`
- `harmonicCoord`

未接続なのは、正値条件の下で指数交換の等式を `gapQ` の零点へ移す theorem である。この候補は数論 spine に依存しないため、別 checkpoint として並行実装できる。

## 4. 新しい実装可能定理候補

### 候補 1: GN Boundary/GN 二チャネル定理群

数学名: **冪差 Body の Boundary/GN 分解定理**

第一候補の識別子:

```lean
prime_dvd_boundary_or_GN_of_dvd_body
prime_dvd_GN_of_dvd_body_of_not_dvd_boundary
boundary_GN_coprime_of_existing_hypotheses
```

想定する最小形は、`BodyN d x u = x * GN d x u` を使って次である。

```lean
Nat.Prime q → q ∣ BodyN d x u →
  q ∣ x ∨ q ∣ GN d x u
```

`q ∤ x` の場合の後半は Euclid lemma で直ちに導ける。coprime 版では、既存の `coprime_boundary_GN_of_coprime_add_of_coprime_exp` を consumer として使い、新しい gcd 理論を追加しない。

価値は、既存の数論事実を増やすことではなく、後続の Prime Gauge 文書が使う `Boundary channel` / `GN channel` という意味上の分岐を、kernel-checked theorem 名で固定することにある。

### 候補 2: 素数次 GN–cyclotomic exact bridge

数学名: **素数次 GN 円分表示定理**

候補識別子:

```lean
GN_one_eq_cyclotomic_eval
eval_GNPolynomial_eq_GN_one
GNPolynomial_isEisensteinAt
```

候補定義は、既存 `GN` を再定義せず、整数係数多項式を別名で置く形である。

```lean
def GNPolynomial (p : ℕ) : Polynomial ℤ :=
  (Polynomial.cyclotomic p ℤ).comp (Polynomial.X + 1)
```

素数 `p` と自然数 `g` に対し、次の等式を評価 bridge として狙う。

```text
Polynomial.eval (g : ℤ) (GNPolynomial p) = (GN p g 1 : ℤ)
```

正確な `Polynomial` の namespace、`C 1` の表記、`eval` の向きは実装 checkpoint で `#check` して確定する。Eisenstein 部分は mathlib の既存 `cyclotomic_comp_X_add_one_isEisensteinAt` を再利用し、DkMath 側では `GNPolynomial` への薄い rewrite に留める。

依存順は次である。

1. `GN` と斉次等比和の評価一致
2. `GNPolynomial` と `cyclotomic p` の shifted evaluation
3. `p` 素数での Eisenstein wrapper
4. `GN5` への compatibility corollary

`Eisenstein` から primitive prime の存在や FLT の完成を推論することは、この候補の scope 外である。

### 候補 3: unit Boundary / 整数 Prime Gauge bridge

数学名: **単位 Boundary による GN 素方向包装定理**

候補識別子:

```lean
body_one_eq_GN
prime_dvd_body_one_iff_dvd_GN
freshPrimeDirection_GN_of_primitivePrimeFactor
primeGaugeTarget_of_freshPrimeDirection
```

最初の二つは `x = 1` の正規化を表す薄い theorem とする。後半は新しい `PrimeGaugeWitness` structure を増やさず、既存の `FreshPrimeDirection` を使う。

```text
BodyN d 1 u = GN d 1 u
q ∣ BodyN d 1 u ↔ q ∣ GN d 1 u
primitive prime witness → FreshPrimeDirection S (GN d 1 u) q
```

なお `freshPrimeDirection_GN_of_primitivePrimeFactor` 自体は現状すでに `StructuralArithmetic.GNBridge` にあるため、新規実装では重複 theorem を作らず、`PrimeGauge` の意味論が本当に追加される場合だけ alias または docstring を加える。

### 候補 4: PowerSwap–GapQ 零点同値

数学名: **正値 PowerSwap–GapQ 零点同値定理**

候補識別子:

```lean
powerSwap_iff_gapQ_eq_zero
powerSwap_iff_harmonicCoord_eq
```

想定形:

```lean
0 < x → 0 < y →
  (Real.rpow x y = Real.rpow y x ↔ gapQ x y = 0)
```

証明は、正値条件から `Real.rpow` を指数と `Real.log` の積へ移し、`Real.exp` の単射性と `gapQ_eq_xy_mul_Hdiff` を使う。`x = 0` または `y = 0` を許した全域同値にはしない。

この候補は Prime Gauge とは独立であり、数論路線の build を不安定にしない別 checkpoint とする。

## 6. 非目標・停止条件

次はこの候補文書から導かれる実装目標ではない。

- squarefree GN だけから、仮定なしの一般 FLT を閉じること
- primitive prime の存在だけから no-lift または valuation `≤ 1` を得ること
- `PHZ30` の candidate seat を actual prime と同一視すること
- finite prime-world refinement から Legendre theorem、Twin Prime theorem、無限 prime existence を得ること
- `PrimeGauge` を実数上の通常の primality と定義すること
- GN–cyclotomic–Eisenstein bridge から自動的に FLT または RH を結論すること
- `gapQ = 0` の branch bridge から PowerSwap の全解分類を結論すること
- 連続極限や反転射影の全射性から整数 prime realization を結論すること

次のいずれかに当たったら、その checkpoint で停止して報告する。

1. 既存 theorem の前提が候補 statement より強く、自然な wrapper に縮約できない。
2. `Polynomial` の型変換が大きな新規代数理論を要求する。
3. proof が `..._research` または新しい `sorry` / axiom に依存する。
4. candidate seat と actual prime の区別を statement で維持できない。
5. FLT/Jacobian の抽象化が具体 theorem の再利用より先行する。

## 7. 結論

2026-09-01 時点の最短で検証可能な実装列は、次の通りである。

```text
existing GTail / GN / valuation / finite-world APIs
        ↓
PGN-001  Boundary/GN channel wrappers
        ↓
PGN-002  GN ↔ shifted cyclotomic evaluation
        ↓
PGN-003  x = 1 unit Boundary / integer fresh-direction packaging
        ↓
PGN-004  PowerSwap ↔ gapQ zero locus  (independent branch)
        ↓
PGN-005  FLT/GN/Jacobian concrete projection demo
```

この列は、既存定理の再証明を避けながら、数論の exact core、有限 prime observer、解析的 observer、FLT projection を段階的に接続する。新しい研究仮説が必要になる境界では、定理候補ではなく research contract として記録して停止する。
