# DkMath.RH.CFBRC によるリーマン予想形式化ドキュメント

## 1. この文書群の目的

このディレクトリでは、`DkMath.RH.CFBRC` Framework を基礎として実装されるリーマン予想の形式化について、数学的内容、Lean 4 実装、依存関係、検証結果、未解決の Gap を日本語で記録する。

目的は、単に実装履歴を残すことではない。各定義・補題・定理が何を主張し、どの仮定に依存し、どこまでリーマン予想へ接続しているかを追跡可能にすることである。

本ディレクトリの文書は、形式化の妥当性を継続的に監査するための記録でもある。

## 2. 正本と言語

日本語版を正本とする。

英語版を作成する場合は、日本語正本の翻訳として扱う。数学的主張、Lean の識別子、定理の依存関係、証明済みと未証明の区別は、日本語正本と一致させる。

翻訳によって主張を強めたり、未証明の内容を証明済みとして記述したりしない。

## 3. ファイル名と採番

文書は作成順に四桁で採番する。

```text
0001-*.md
0002-*.md
0003-*.md
```

番号は文書の作成順を表し、理論上の重要度や証明依存順を直接表すものではない。

既存番号は再利用しない。文書を廃止する場合も番号を保持し、廃止理由と後継文書を明記する。

## 4. 記録対象

各文書では、必要に応じて次の事項を記録する。

1. 対象となる Lean module と主要識別子
2. 数学的主張と通常数学による解釈
3. 使用する仮定と型クラス

10. 未証明の Gap、obstruction、監査上の注意

## 5. 妥当性監査の基本原則

### 5.1 Lean Green と数学的完成を区別する

Lean の build が成功したことは、そのファイルに記述された命題がカーネルにより検証されたことを意味する。

ただし、命題の仮定が目的に対して十分であること、定義が標準的対象を正しく表していること、リーマン予想への接続に循環がないことは別途監査する。

### 5.2 同値な言い換えを進展と誤認しない

リーマン予想と同値な bridge theorem を構成しただけでは、リーマン予想を証明したことにはならない。

特に、標準ゼータ関数の非自明零点を CFBRC 零点へ写す仮定が、既にリーマン予想と同値である場合、その仮定の供給が主 Gap であることを明記する。

### 5.3 同一対象上の衝突を要求する

矛盾証明では、zero-forced と nonzero-forced が同じ Lean object、同じ正規化、同じ極限、同じ index discipline に対して成立していることを確認する。

単に正の数列が零へ収束すること、異なる moving frame 上の量を比較すること、異なる添字 shift を省略することは矛盾を与えない。

### 5.4 可視化・数値実験・着想を Core と区別する

可視化、数値計算、会話上の着想、物理的比喩は、定義や証明候補を発見する資料として有用である。

しかし、それらは Lean により証明された Core theorem とは区別して記録する。

## 6. CFBRC 文書で用いる状態分類

各主要項目には、可能な限り次の状態を付す。

```text
Core
Lean で証明済みの定義、恒等式、評価、極限、排除定理

Beam
Core から最終目標へ伸ばしている候補経路

Gap
最終目標へ到達するために不足している数学的橋

Obstruction
特定の証明経路が閉じないことを固定した監査結果

Big
Core、Beam、Gap を統合して得る最終定理
```

概念的には次の関係で管理する。

$$
\mathrm{Big}=\mathrm{Core}+\mathrm{Beam}+\mathrm{Gap}
$$

Gap を証明済み Core として扱わない。

## 7. 数式と Markdown の記述規則

数式はインライン TeX またはブロック TeX を使用する。

ブロック数式は、区切りを含めて独立した行に置く。

```text
$$
F(x)=0
$$
```

数式中の `=` や `-` を Markdown の行頭記号と誤認させないようにする。特に、数式の継続行を `=` だけで開始しない。

不要な細分化や細かな改行を避け、通常の段落として読める形を保つ。

Lean code、module 名、定理名、branch 名、commit SHA はコード記法で表す。

## 10. 現在の開始点

本ドキュメント整備は、`DkMath.RH.CFBRC` に既に蓄積された形式化を、証明済み Core、進行中 Beam、未完成 Gap、閉じない Obstruction に分解して再読するところから始める。

最初の監査では、次の三点を特に重視する。

1. CFBRC 側で証明済みの零点幾何
2. Mathlib の標準リーマンゼータ関数および `RiemannHypothesis` との接続
3. 標準ゼータの非自明零点を CFBRC 零点へ写す主 Gap

この三層を混同せず、各定理が実際に閉じている範囲を文書化していく。
