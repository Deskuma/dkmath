## 2. Pair integrability is sufficient

The theorem

```lean
mellinQuadraticBoxGramPairIntegrand_intervalIntegrable
```

shows that every unnormalized pair integrand is interval-integrable on the finite interval.

The remaining normalized summand merely multiplies this function by the constant complex scalar

```text
((2 * ε : ℝ)⁻¹ : ℂ)
```

so no new analytic estimate is required.

The double family is finite.  Therefore the remaining exchange is finite linearity only:

```text
sum_i sum_j integral(pair i j)
  = integral(fun t => sum_i sum_j pair i j t)
```

There is no Fubini theorem, Tonelli theorem, dominated convergence, infinite series, or limit operation here.

## 5. Finset binder / intervalIntegral API mismatch strategy

The remaining obstacle is an API-shape problem, not a mathematical gap.

If the installed interval-integral finite-sum theorem does not elaborate cleanly under nested `∑ i, ∑ j`, do not leave a half-proved permanent theorem.  Two safe proof architectures are available.

### Route A — nested finite-sum linearity

Prove an inner helper for fixed `i`:

```text
sum_j integral(pair i j)
  = integral(fun t => sum_j pair i j t)
```

then apply the same pattern to the outer `i` sum.

This keeps each integrability obligation local and usually aligns better with Mathlib's binder elaboration.

### Route B — finite induction fallback

If the binder API remains awkward, prove the finite-sum/integral exchange by `Finset` induction, using only:

```text
integral_zero
integral_add
```

with the existing pairwise interval-integrability theorem.

Because the index sets are finite, this is completely adequate and avoids depending on a fragile binder-specific rewrite lemma.

Prefer whichever route compiles more cleanly.  The mathematical theorem surface should remain the same.

## 6. Normalization audit

The current implementation has the normalization in the correct place.

`mellinQuadraticBoxGram_pair_eq_integral` places

```text
((2 * ε : ℝ)⁻¹ : ℂ)
```

inside the pairwise integral.

`mellinQuadraticBoxGramEnergy_eq_normalized_double_sum_integral` places the same scalar once outside the common integral.

When summing the pairwise identities, linearity should move the common scalar out exactly once.

No extra factor of `(2 * ε)⁻¹` should appear.

The target normalization is:

$$
Q_\varepsilon(z,c)=(2\varepsilon)^{-1}\int_{-\varepsilon}^{\varepsilon}G_{z,c}(t)\,dt.
$$

not a squared normalization.
