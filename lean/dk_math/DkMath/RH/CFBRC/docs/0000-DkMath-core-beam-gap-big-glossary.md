# DkMath 用語集 — Core・Beam・Gap・Big

## 1. この文書の位置付け

この文書は、`DkMath.RH.CFBRC` の形式化文書で使用する DkMath 固有用語を説明するための用語集である。

`0001` 以降の文書では、`Core`、`Beam`、`Gap`、`Big` などの語を、DkMath の研究・形式化哲学に基づく技術用語として使用する。そのため、通常の数学・Lean・ソフトウェア開発だけを知る読者には、これらの意味が自明とは限らない。

`0000-*.md` は、採番された本編文書に先立つ辞書・定義・記法の層として扱う。

`0000` 番号のファイルは複数存在してよい。用語、定義、記法、設計哲学、監査規則などをカテゴリ別に分け、必要に応じて随時追記する。文書群が安定した段階で、重複を整理し、一つの統合用語集へまとめることができる。

## 2. DkMath における証明状態の基本分解

DkMath では、形式化の現在地を次の四つの状態に分けて考える。

```text
Core
Beam
Gap
Big
```

必要に応じて、閉じない経路を記録する `Obstruction` も加える。

これらは単なる進捗ラベルではない。何が証明され、何が候補であり、何が不足し、最終主張がどの成分から構成されるかを混同しないための論理的分類である。

## 3. Core

### 3.1 定義

`Core` は、Lean のカーネルにより検証された、現在動かす必要のない確定部分である。

典型例は次のとおりである。

1. 定義
2. 有限恒等式
3. 型が明示された補題
4. 評価不等式
5. 極限定理
6. 同値定理
7. 排除定理
8. 反例または不可能性定理

Lean の build が Green であり、対象 module が正しい import 経路から検査されていることが、Core と呼ぶための基本条件になる。

### 3.2 Core が意味しないもの

Core であることは、その命題が最終目的を達成したことを意味しない。

例えば、次の定理が Lean で証明されているとする。

$$
\operatorname{offCriticalCFBRC}(d,\sigma,\Theta)=0\iff\sigma=\frac12
$$

これは CFBRC 零点集合の構造に関する強い Core である。

しかし、標準リーマンゼータ関数の非自明零点が実際にこの CFBRC 零点へ写ることが未証明なら、リーマン予想そのものはまだ得られていない。

したがって、Core は「証明済みの部品」であり、「最終定理全体」とは区別する。

## 4. Beam

### 4.1 定義

`Beam` は、既存 Core から最終目標へ向かって伸びる、証明候補の経路である。

Beam には、次のようなものが含まれる。

1. 既存補題を組み合わせる予定の proof route
2. 解析対象と代数対象を接続する bridge 候補
3. 有限模型から無限極限へ進む経路
4. zero-forced と nonzero-forced を衝突させる候補
5. mirror、energy、factorization、phase、center などを使う証明設計

Beam は、数学的に有望であっても、まだ Core ではない。

### 4.2 Beam の扱い

Beam を文書化するときは、少なくとも次を明記する。

```text
入力となる Core
狙う出力
必要な未証明補題
同一対象性
正規化
添字規則
失敗した場合の判定条件
```

Beam が閉じなかった場合、その経路を削除して忘れるのではなく、なぜ閉じなかったかを `Obstruction` として残すことがある。

## 5. Gap

### 5.1 定義

`Gap` は、Core と最終目標の間に実際に不足している数学的橋である。

単にコードが未記述であることを意味しない。既存 API を呼び出せば済む実装作業と、数学的に新しい主張が必要な Gap は区別する。

### 5.2 主 Gap と補助 Gap

Gap は重要度により区別できる。

```text
主 Gap
最終定理と同等、またはそれに近い数学的内容を持つ不足

補助 Gap
主経路を形式化するために必要だが、独立には比較的小さい不足
```

例えば、標準ゼータ関数の非自明零点を CFBRC 零点へ写す命題が、既にリーマン予想と同値であると証明されているなら、その `map_zero` の供給は主 Gap である。

一方、添字を `K` から `K+1` へ移す極限補題や、実軸上で虚部が零である場合を処理する補題は、補助 Gap になりうる。

### 5.3 Gap を隠さない

DkMath 文書では、次のような表現を避ける。

```text
ほぼ証明済み
あとは接続するだけ
形式的には完成
```

残っている接続が主定理と同値なら、それは小さな仕上げではない。

Gap は不足として明示し、Core に含めない。

## 6. Big

### 6.1 定義

`Big` は、最終的に達成したい全体構造である。

DkMath の考え方では、Big は単独で突然現れるものではなく、Core、Beam、Gap の関係として追跡する。

概念的には次のように表す。

$$
\mathrm{Big}=\mathrm{Core}+\mathrm{Beam}+\mathrm{Gap}
$$

この式は通常の数値加算ではない。

- Core は既に確定した部分
- Beam は目標へ向かう構成経路
- Gap はその経路で未充足の義務
- Big は全義務が満たされた完成状態

を表す構造式である。

### 6.2 RH-CFBRC における Big

本ディレクトリでの主要な Big は、Mathlib の `RiemannHypothesis` を仮定なしで構成する Lean theorem である。

Big と呼ぶためには、少なくとも次が必要になる。

1. 標準ゼータ関数の非自明零点 predicate との正確な一致
2. CFBRC 零点が臨界線に限られる Core
3. 全非自明零点を CFBRC 零点へ写す無条件 bridge
4. 仮定の循環がないこと
5. 同一対象・同一極限上の collision
6. 公開 import 経路からの full build Green

## 7. Obstruction

### 7.1 定義

`Obstruction` は、ある Beam が指定した条件では閉じないことを示す、名前付きの監査結果である。

失敗した試みを単なる失敗ログとして捨てるのではなく、再び同じ誤った経路へ戻らないための Core として保存する。

### 7.2 典型例

次のような結果は Obstruction になりうる。

1. 三角不等式による粗いノルム評価では定数が不足する
2. moving frame と fixed frame の量を同一視できない
3. eventual positivity と零への収束だけでは矛盾にならない
4. finite closure が reverse-negate により人工的に作られている
5. bridge の仮定が結論と同値であり、独立な進展を与えない

Obstruction は否定的な成果ではない。証明空間を狭める確定情報である。

## 8. Core / Beam / Gap / Big の具体例

RH-CFBRC の現在地を抽象化すると、次のように整理できる。

```text
Core:
  offCriticalCFBRC の零点は σ = 1/2 に限られる

Beam:
  標準ゼータ零点を CFBRC closure へ写す解析的構成

Gap:
  全非自明零点に対する無条件 map_zero

Big:
  Mathlib.RiemannHypothesis
```

ここで、Core から直ちに Big が出るわけではない。

必要なのは、標準ゼータ零点集合を CFBRC 零点集合へ含める Beam を実体化し、その Gap を埋めることである。

## 9. トロミノ論法との対応

DkMath では、不足部分を空白として明示する説明法を、トロミノ論法と呼ぶことがある。

三つの確定した正方形と一つの空白を持つ L 型トロミノのように、証明全体を、埋まった部分と不足部分へ分けて見る。

```text
証明済みの三領域
  Core
  Core から得られる帰結
  Beam の確定部分

空白の一領域
  Gap
```

空白を想像で埋めず、Gap として可視化することが重要である。

Gap が埋まったとき、局所的な構成が一つの Big へ閉じる。

## 10. 一般的な数学用語との違い

`core`、`gap`、`beam`、`big` は英語の一般語としても使われるが、本ディレクトリでは大文字で始めた場合、原則として本書の DkMath 定義を指す。

```text
Core
Beam
Gap
Big
Obstruction
```

通常の意味で使う場合は、日本語で「中心部分」「差」「大きい」などと書き分ける。

## 11. 文書での推奨表記

各形式化文書では、冒頭または結論部に次のような状態表を置くことを推奨する。

```text
Core:
  Lean で確定した主張

Beam:
  現在採用している証明経路

Gap:
  未証明の load-bearing obligation

Obstruction:
  既に閉じないと判明した経路

Big:
  最終的に得る theorem
```

これにより、一般読者も「何が既に証明され、何が研究中なのか」を追跡できる。
