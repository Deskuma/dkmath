## B. Generic discriminant-axis primality

For a `PrimeDiscriminantPacket p s`, audit whether the existing norm/divisibility
API is sufficient to prove that `discrAxis s` is a prime element whenever
`TraceOneInt s` is a domain.

The intended proof is through the already-proved equivalence

```text
discrAxis s | x  <->  p | natAbs (norm x)
```

and multiplicativity of the norm:

```text
p | natAbs (norm (x*y))
-> p | natAbs (norm x) * natAbs (norm y)
-> p | natAbs (norm x) or p | natAbs (norm y)
-> discrAxis s | x or discrAxis s | y.
```

Also prove nonzero / nonunit as required by the pinned `Prime` API without
assuming a Euclidean or GCD domain.

Suggested endpoint shape, adjusted to the actual pinned API:

```lean
PrimeDiscriminantPacket.prime_discrAxis
```

Do not install a broad global instance.

## D. Ideal-level conjugate coprimality from primitive coordinates

The generic endpoint should be ideal-theoretic, not `gcd`-based.

For

```text
w : TraceOneInt s
```

assume

```text
IsCoprime w.fst w.snd
¬ discrAxis s | w
```

and the prime-discriminant / Dedekind hypotheses.

Prove:

```text
IsCoprime (Ideal.span {w}) (Ideal.span {conj w})
```

Suggested route:

1. From coordinate coprimality and Part A, show that the ideal
   `Ideal.span {w} ⊔ Ideal.span {conj w}` contains `discrAxis s`.
2. Hence `Ideal.span {discrAxis s}` is below that sum ideal.
3. By maximality of the axis ideal, the sum is either the axis ideal or `top`.
4. The axis-ideal case would imply `discrAxis s | w`, contradicting terminality.
5. Therefore the sum is `top`, hence the two principal ideals are coprime.

Avoid introducing a `GCDMonoid` instance merely to reproduce the p=7 element
gcd proof.

Suggested public theorem family:

```lean
ideal_isCoprime_span_conj_of_coordinate_coprime_of_axis_terminal
```

Exact names should follow current DkMath naming conventions.

This part is the mandatory GREEN target for Phase 21.

## E. Axis stripping and norm p-th-power normalization

Connect the generic discriminant-axis depth API to the Phase-1/13 shape.

For the ramified residual from `PrimeAdicPowerSplit`, Phase 1 gives

```text
GTail p 1 g u = p * b^p
p ∤ b.
```

Phase 13 gives a TraceOne element `alpha` with

```text
norm alpha = GTailCyclotomicShell p g u
```

(after using the existing GTail/shell bridge under the required nonzero
hypothesis).

Audit and, if feasible, package the exact one-axis stripping statement:

```text
alpha = discrAxis s_p * residual
```

with terminal residual and

```text
norm residual = b^p          if D_p = -p
norm residual = -(b^p)       if D_p = +p.
```

Since `p` is odd, the real-branch sign should be expressible as

```text
-(b^p) = (-b)^p.
```

A useful neutral packet may record simply

```text
∃ beta : TraceOneInt s_p,
  alpha = discrAxis s_p * beta ∧
  ¬ discrAxis s_p | beta ∧
  ∃ c : ℤ, norm beta = c^p.
```

Do not force a packet type if a theorem family is cleaner.

This part may depend on reconciling `GTail p 1` with
`GTailCyclotomicShell p`; use existing production bridges rather than
re-proving the polynomial identity.

## F. The actual remaining primitive-coordinate theorem

Now isolate the genuinely nontrivial question.

Phase 13 currently provides existential integral polynomials `AZ`, `SZ` such
that

```text
norm <AZ(z,y), SZ(z,y)> = GTailCyclotomicShell p (z-y) y.
```

Test first whether one can prove, for primitive endpoints,

```text
Nat.Coprime z y
-> IsCoprime (eval AZ z y) (eval SZ z y)
```

or an equivalent statement strong enough for Part D after one axis is
stripped.

Do not assume this merely because it holds for p=7.

Audit both plausible routes:

### F1. Polynomial / resultant route

Look for a theorem that a common prime divisor of the two Gauss-coordinate
forms forces a common divisor of `z` and `y`, perhaps via a resultant or a
Bezout identity between the homogeneous coordinate polynomials.

### F2. Cyclotomic QR/QNR route

Use the Phase-7 root-factorization viewpoint.  A common prime/ideal divisor of
the quadratic conjugate factors should be supported only at the ramified prime
`p`; after discriminant-axis stripping, this may imply coordinate primitivity
without an explicit resultant computation.

Prefer whichever route makes the fewest new assumptions.

If neither closes in the pinned Mathlib/DkMath API, stop honestly and report the
smallest missing theorem.  Do not insert a receiver assumption into production
and label it GREEN.
