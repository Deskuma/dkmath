# Visual Storyboard

## DkMath — Cosmic Formula Inversion

This document defines the visual narrative for the primary hackathon demonstration.

It translates the verified mathematical contract into a short Manim sequence without adding new mathematical claims.

The governing rule is:

```text
Lean proves the theorem.
Manim reveals the structure.
The narration explains the connection.
```

The visual layer must remain downstream of:

```text
MATHEMATICAL_CONTRACT.md
DECISIONS.md
DEMO_CONTRACT.md
```

If a visual idea conflicts with the formal theorem surface, the visual idea must be changed.

## 2. Primary Visual Thesis

The animation presents one continuous transformation:

```text
known finite prime set
→ product P
→ arithmetic Body
→ missing Gap
→ completed square
→ completed boundary P + u
→ fresh factors outside the original set
→ Lean verification
```

The intended viewer takeaway is:

> A finite set of known primes is multiplied into `P`.  
> A coprime offset `u` completes a Cosmic Formula square.  
> The completed side length `P + u` has prime factors outside the original finite set.  
> Lean verifies the arithmetic statement.

The animation must not imply that the geometric rearrangement causes prime factorization.

Preferred representation:

```text

```

Alternative:

```text

```

The merge should communicate arithmetic composition, not physical fusion as a theorem.

### Body

Preferred initial representation:

```text

```

The rectangle may later be rearranged into a gnomon-shaped region.

### Gap


The side label `u = 11` should be visible at least once.

### Big

Preferred representation:

```text
a completed square with side P + u
```

The completed square should visually resolve the prior open or missing region.

## 7. Scale Policy

The actual numerical dimensions are too large for literal screen scaling.

Therefore the animation uses schematic geometric proportions.

Rules:

```text
The displayed rectangle and square represent the algebraic quantities.

Lengths do not need to be pixel-proportional to 210, 232, or 221.

Labels must make the exact values explicit.

The visual transformation must preserve the symbolic identity.

The animation must not claim a literal scale drawing.
```

A small caption may state:

```text
schematic geometry — exact arithmetic verified in Lean
```

## 31. Schematic Geometry Construction Options

### Option A — Rectangle Plus Gap Square

```text

```


### Option B — Gnomon Rearrangement

Split the Body into two rectangles:

```text

```

Rearrange around the `u × u` Gap to form the `(P + u) × (P + u)` square.

Advantages:

```text

```

```text

```

---

### Option C — Algebra-First Morph

Start with:

$$
P(P+2u)+u^2
$$

Expand:

$$
P^2+2Pu+u^2
$$

Then morph into:

$$
(P+u)^2
$$

while the geometry follows.

Advantages:

```text

```

Risk:

```text
less immediate for general viewers
```

---

### Recommended Initial Choice

Use a hybrid of Options B and C.

```text
show the Body geometrically
show the Gap square
briefly display the algebraic identity
close the outer square
```

The first prototype should test whether the gnomon layout remains readable within the time budget.
