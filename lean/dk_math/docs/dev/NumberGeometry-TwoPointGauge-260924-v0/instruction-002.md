NGEO-001 has frozen the production core:

~~~lean
abbrev Point := EuclideanSpace ℝ (Fin 2)

def pairVec (A B : Point) : Point := B - A

def pairMass (A B : Point) : ℝ := ‖pairVec A B‖ ^ 2

structure TwoPointKernel where
  source : Point
  target : Point

def TwoPointKernel.Active (K : TwoPointKernel) : Prop :=
  K.source ≠ K.target
~~~

and proved the zero / positivity interface:

~~~text
pairMass A B = 0  <-> A = B
0 < pairMass A B  <-> A != B
~~~

## Objective

Implement the first relative arithmetic layer generated by an active
two-point kernel.

The guiding principle is:

~~~text
the pair (A,B) supplies the unit gauge;
a point P is counted by its square-mass ratio to that gauge.
~~~

The production API should remain denominator-free whenever possible.

The central predicate is:

~~~text
pairMass K.source P = n * pairMass K.source K.target
~~~

for n : Nat.

This checkpoint should formalize:

- the distance/mass gauge carried by a two-point kernel;
- natural-number counting shells;
- shell 0 and shell 1;
- the mass form of the successor law;
- a secondary normalized-mass quotient view under K.Active.

Do not implement similarity transport yet; that is NGEO-003.

Do not implement radical landing, prime scale, UnitCycle, logarithms, 2p
phases, or FLT.

## 1. Gauge definitions

The base distance itself is already owned by mathlib dist.

Do not introduce another independent distance function.

Define semantic gauge accessors only if they are useful as stable API.

Preferred minimal forms:

~~~lean
def distanceGauge (K : TwoPointKernel) : ℝ :=
  dist K.source K.target

def massGauge (K : TwoPointKernel) : ℝ :=
  pairMass K.source K.target
~~~

If distanceGauge is only an alias with no useful theorem surface, it may be
omitted in favor of dist K.source K.target. massGauge is more likely to be
worth naming because it is the arithmetic unit of the new theory.

Whatever names are chosen, document that the gauge is relative: no assumption
that the base distance is numerically 1 is made.

## 2. Natural counting shell

Introduce the denominator-free predicate:

~~~lean
def OnNatShell (K : TwoPointKernel) (n : ℕ) (P : Point) : Prop :=
  pairMass K.source P = (n : ℝ) * massGauge K
~~~

If massGauge is not introduced, use the expanded pairMass form directly.

The cast to ℝ should be explicit in the definition.

The predicate must be meaningful even for a degenerate kernel. Degenerate
behavior is not an error; later theorems that divide by the gauge will require
K.Active.

## 3. Required shell theorems

At minimum prove:

~~~lean
@[simp] theorem onNatShell_zero_source (K : TwoPointKernel) :
  OnNatShell K 0 K.source

@[simp] theorem onNatShell_one_target (K : TwoPointKernel) :
  OnNatShell K 1 K.target
~~~

Also prove the direct unfolding form if useful:

~~~lean
theorem onNatShell_iff (K : TwoPointKernel) (n : ℕ) (P : Point) :
  OnNatShell K n P ↔
    pairMass K.source P = (n : ℝ) * pairMass K.source K.target
~~~

Consider, if useful:

~~~lean
theorem onNatShell_zero_iff (K : TwoPointKernel) (P : Point) :
  OnNatShell K 0 P ↔ P = K.source
~~~

This should follow from pairMass_eq_zero_iff.

For an active kernel, shell 1 contains the target. Do not claim that the target
is the unique shell-1 point: an entire circle/sphere of points can have the
same distance from the source.

That uniqueness claim would be false.

## 4. Active gauge facts

Connect Active to the gauge.

Required if massGauge exists:

~~~lean
@[simp] theorem massGauge_eq_zero_iff (K : TwoPointKernel) :
  massGauge K = 0 ↔ K.source = K.target

theorem massGauge_pos_iff_active (K : TwoPointKernel) :
  0 < massGauge K ↔ K.Active
~~~

A nonzero form is strongly useful:

~~~lean
theorem massGauge_ne_zero_of_active
    (K : TwoPointKernel) (hK : K.Active) :
    massGauge K ≠ 0
~~~

If distanceGauge is introduced, add only the obvious thin bridge:

~~~text
massGauge K = distanceGauge K ^ 2
~~~

Do not create a large parallel distance API.

## 5. Normalized mass quotient view

The primary shell API is denominator-free. Add a secondary normalized view
only under an active-base hypothesis.

Preferred definition:

~~~lean
def normalizedMass (K : TwoPointKernel) (P : Point) : ℝ :=
  pairMass K.source P / massGauge K
~~~

It is acceptable for the definition to exist for all kernels because real
division is total in Lean, but every arithmetic interpretation theorem must
assume K.Active.

Required bridge:

~~~lean
theorem normalizedMass_eq_nat_of_onNatShell
    (K : TwoPointKernel) (hK : K.Active)
    {n : ℕ} {P : Point}
    (hP : OnNatShell K n P) :
    normalizedMass K P = (n : ℝ)
~~~

Prove the converse if equally clean:

~~~lean
theorem onNatShell_of_normalizedMass_eq_nat
    (K : TwoPointKernel) (hK : K.Active)
    {n : ℕ} {P : Point}
    (h : normalizedMass K P = (n : ℝ)) :
    OnNatShell K n P
~~~

If both directions are clean, package the equivalence.

Do not make quotient normalization the primitive definition of OnNatShell.

## 6. Geometric successor mass law

The intended successor is additive in square mass.

Formalize the arithmetic identity that one base mass unit is added.

A good theorem shape is:

~~~lean
theorem pairMass_eq_add_massGauge_of_onNatShell_succ
    (K : TwoPointKernel)
    {n : ℕ} {P : Point}
    (hP : OnNatShell K (n + 1) P) :
    pairMass K.source P =
      (n : ℝ) * massGauge K + massGauge K
~~~

The theorem is not claiming a canonical successor point and does not construct
a point on shell n+1.

It only states the mass law of an already-given shell point.

Do not introduce a succ : Point -> Point map.

## 7. Optional existence calibration

NGEO-002 does not need a global theorem that every n shell is inhabited.

If existence of an explicit shell point can be proved very cheaply by scaling
the target with Real.sqrt n, it may be investigated but must not be added
unless:

- it remains small;
- it does not distract from the core API;
- affine placement relative to K.source is handled correctly;
- all nonnegativity side conditions are clean.

It is fully acceptable to defer shell-existence construction.

Do not force it.

## 8. Root-distance interpretation

The conceptual reading is:

~~~text
OnNatShell K n P
  -> dist(K.source,P)^2 = n * dist(K.source,K.target)^2.
~~~

Add a theorem in squared-distance form using pairMass_eq_dist_sq.

Recommended:

~~~lean
theorem dist_sq_eq_nat_mul_dist_sq_of_onNatShell
    (K : TwoPointKernel)
    {n : ℕ} {P : Point}
    (hP : OnNatShell K n P) :
    dist K.source P ^ 2 =
      (n : ℝ) * dist K.source K.target ^ 2
~~~

Do not yet force the square-root form if it causes unnecessary sign/sqrt proof
overhead.

The squared-distance theorem is the production kernel.
