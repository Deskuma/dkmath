## 3. Q1 — complete prime support

The existing API is sufficient. The canonical set is:

    DkMath.NumberTheory.Primitive.primeScalesUpTo P

with the simp theorem:

    mem_primeScalesUpTo :
      q ∈ primeScalesUpTo P ↔ Nat.Prime q ∧ q ≤ P

This is exactly the requested complete-support predicate. No
PrimeCompleteUpTo definition or canonical finite-set alias should be added.

## 4. Q2 — square-Body monotonicity

No declaration equivalent to either

    q ≤ P → squareBody q ≤ squareBody P
    q ≤ P → (q + 1)^2 ≤ (P + 1)^2

was found in the inspected tree. squareBody_add_one_eq is present and is the
endpoint identity, but it is not a monotonicity theorem. The minimal next
adapter is therefore a square-Body monotonicity lemma, proved from the order
of natural multiplication or from the consecutive-square boundary.

## 5. Q3 — square escape and fresh direction

The existing chain is already complete at the finite arithmetic level:

1. exists_prime_dvd_le_of_not_prime_of_le_squareBody uses the existing
   Nat.minFac square argument and squareBody_add_one_eq to produce a prime
   divisor q ≤ P of any composite 1 < m ≤ squareBody P.
2. prime_of_supportDisjointFrom_le_squareBody contradicts that witness when
   every prime q ≤ P is excluded.
3. supportDisjointFrom_primeScalesUpTo_iff and
   prime_of_supportDisjointFrom_primeScalesUpTo_le_squareBody connect this
   raw condition to the canonical primeScalesUpTo P world.
4. For a specified large prime divisor,
   not_prime_sq_dvd_of_anchor_lt_of_le_squareBody gives depth one, and
   eq_of_large_primes_dvd_le_squareBody gives uniqueness of the fresh prime
   direction.
5. freshPrimeDirection_of_anchor_lt_prime_dvd exposes the direction through
   FreshPrimeDirection.
6. large_prime_cofactor_properties_of_le_squareBody and
   primeScaleGeneratedBy_div_of_large_prime_dvd_le_squareBody give the old
   cofactor; squareBody_large_prime_split packages the result.
7. The global disjunctions
   primeScaleGeneratedBy_or_uniqueFresh_split_of_le_squareBody and
   primeScaleGeneratedBy_or_uniqueFresh_small_split_of_le_squareBody cover
   the old-generated branch and the one-fresh-prime branch.

Thus the current API already uses SupportDisjointFrom, primeScalesUpTo,
PrimeScaleGeneratedBy, and FreshPrimeDirection with their intended separate
meanings. No semantic wrapper is needed for PCK-000.

## 6. Q4 — coarse primorial anchor interface

The finite basis interface is present without redefining a primorial:

    S
      -> finitePrimeBasisProduct S
      -> IsCommonMultipleOfPrimeBasis / periodicity
      -> ReservedByPrimeBasis and wheel survivors
      -> fresh-prime lift and unique deletion

The product-plus-one route is also present through
finitePrimeBasisEscapePoint and
exists_new_prime_divisor_of_finitePrimeBasis. The refinement route is
present through primeBasisWheelLift,
existsUnique_freshPrime_dvd_lift, and
existsUnique_reservedByPrimeBasis_insert_fresh_lift.

The canonical regression is direct:

    finitePrimeBasisProduct ({2, 3, 5} : Finset ℕ) = 30

with the required IsFinitePrimeBasis proof by the existing concrete norm_num
pattern. No prime-existence assumption is introduced.

## 7. Q5/Q6 — basis versus complete closure and the canonical 30 → 960 route

These objects are distinct:

| object | current owner | meaning |
|---|---|---|
| primeWorld235 = {2,3,5} | Primitive/PHZ30.lean | generating finite basis; KnownPrimeScales primeWorld235 |
| finitePrimeBasisProduct primeWorld235 | PrimorialUniverse/FinitePrimeSynchronization.lean / PHZ30 bridge | coarse period/anchor, equal to 30 |
| primeBasisWheelSurvivors {2,3,5} and phzResidues30 | WheelSurvivor.lean / Primitive/PHZ30.lean | seats that avoid only the selected basis primes; not a primality predicate |
| primeScalesUpTo 30 | Primitive/FinitePrimeWorld.lean | complete set of all primes at most 30, by mem_primeScalesUpTo |

In particular, coprimality with 30 is only basis-survivor information. It
does not certify primality through 960; 49 is coprime to 30 but is composite.

The exact generic route for the requested statement is:

    finitePrimeBasisProduct {2,3,5} = 30
    30 * (30 + 2) = 960
    squareBody 30 + 1 = (30 + 1)^2 = 31^2
    primeScalesUpTo 30 = {q | Nat.Prime q ∧ q ≤ 30} -- via membership

For 1 < m ≤ 960, assume:

    ∀ ⦃q : ℕ⦄, Nat.Prime q → q ≤ 30 → ¬ q ∣ m

Then instantiate prime_of_supportDisjointFrom_le_squareBody with P = 30,
or first convert the assumption with
supportDisjointFrom_primeScalesUpTo_iff.mpr and instantiate
prime_of_supportDisjointFrom_primeScalesUpTo_le_squareBody with P = 30.
The conclusion is Nat.Prime m.

There is no separate numeric 30 → 960 theorem in the inspected source, and
adding one is not necessary for PCK-000: the generic theorem is already the
shortest route. The equalities squareBody 30 = 960 and
960 + 1 = 31^2 are routine numeral instantiations of the existing definition
and endpoint theorem.

## 8. Q7 — coarse-to-fine gap

The desired implication

    q ≤ P
    m ≤ squareBody q
    support-disjoint from all primes ≤ P
    ⇒ Nat.Prime m

is not present as a named theorem. It follows immediately once the missing
monotonicity adapter is supplied:

    m ≤ squareBody q
      ≤ squareBody P

then apply prime_of_supportDisjointFrom_le_squareBody with anchor P (or its
primeScalesUpTo wrapper). The smallest next bridge is:

    squareBody_mono : q ≤ P → squareBody q ≤ squareBody P

plus, if the next consumer wants the support-set spelling, one thin theorem
that composes this inequality with the existing square certification theorem.
No new prime framework or wheel implementation is needed.

## 9. Q8 — half-unit zero-conjugate overlap

Classification: THIN-ADAPTER-NEEDED.

The inspected existing owners provide nearby ingredients but not the requested
canonical package:

- CosmicFormula/CoreBeamGap.lean owns the Core + Beam + Gap binomial
  decomposition, not the quadratic in q/2.
- CosmicFormula/CosmicFormulaPythagoras.lean owns generic identities such as
  sq_sub_sq_gap_beam and sq_diff_of_gap. These can algebraically supply the
  displayed identity after a suitable substitution, but neither theorem names
  q, midpoint, roots, or unit-depth.
- PrimorialUniverse/UnitCoordinateRefinement.lean owns positive real units,
  coordinate transport, and prime-to-nonprime refinement. It does not define
  the zero-conjugate quadratic.
- FLT/PhaseLift.lean has a separate HasNPHalfStepWitness over NP and ℚ; this
  is not the requested real quadratic/midpoint/depth interface.
- The square-anchor phase files contain modular lift-index midpoint results,
  but not the stated polynomial identity and its two real roots.

Consequently a later focused adapter may define the q-indexed zero-conjugate
quadratic and prove, with explicit type assumptions, its factorization, roots,
midpoint, and depth. PCK-000 does not create HalfUnitZeroConjugate.lean.
