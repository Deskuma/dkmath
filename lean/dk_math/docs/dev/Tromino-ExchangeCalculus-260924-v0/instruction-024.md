# TRM-025 — Connected combinatorial-map certificate / arithmetic genus

## Goal

Introduce the strong combinatorial-map wrapper under which the Euler count
from TRM-024 can legitimately be read as the usual V/E/F permutation data.

Important correction/boundary:

TRM-024 intentionally allows any FlowLocalRotation. In that weak setting
V := N.regionCount need not equal the number of rotation cycles.

For a surface-style combinatorial map, each region must carry one cyclic
rotation orbit. Therefore genus/Euler interpretation must require
FlowRotationSystem, not merely FlowLocalRotation.

The existing 2×4 identity-rotation fixture has chi = 2 but is **not** a
FlowRotationSystem: each region has four singleton rotation orbits.
Do not use it as a sphere/genus-zero calibration.

TRM-025 should define a connected strong map certificate and an arithmetic
genus relation, but must still stop short of any topological realization or
planarity theorem.

## A. Strong connected map wrapper

Define a structure along the lines of:

```lean
structure FlowCombinatorialMap (N : FlowNetwork) where
  crossing : FlowCrossing N
  rotation : FlowRotationSystem N
  nonemptyRegions : 0 < N.regionCount
  connected : ∀ r s : Fin N.regionCount,
    RegionReachable crossing r s
```

Naming may be adjusted, but the fields must express:

- fixed-point-free crossing involution;
- one cyclic rotation orbit per region;
- at least one region;
- connected underlying region multigraph.

Do not include labels/potential/zero-holonomy assumptions beyond what
FlowNetwork already carries.

This is combinatorial-map data, not a planar map claim.

## C. Why strong cyclicity matters

Provide theorem-level calibration showing that every port in a fixed region
lies in the same rotation orbit, directly from M.rotation.cyclic.

If useful define:

Do not build a second full orbit partition unless necessary.

  cycles of rho;
- for weak FlowLocalRotation this alignment is not guaranteed.

## D. Connectedness calibration

Prove basic consequences of M.connected:

- RegionReachable M.crossing r s for all r,s;
- the underlying regionSimpleGraph is connected/reachable if the Mathlib
  bridge is cheap.

The Mathlib connectedness bridge is optional.

More useful is a port-level generated-connectivity statement if it is
tractable:

Given p q : FlowNetworkPort N, there exists a finite sequence of operations
generated by:

- local rotation rho / rho^{-1};
- crossing alpha

taking p to q.

This theorem is optional for TRM-025; do not let it block the checkpoint.

## E. Arithmetic combinatorial genus relation

Define:

```lean
def HasCombinatorialGenus (M : FlowCombinatorialMap N) (g : Nat) : Prop :=
  M.eulerCharacteristic = (2 : Int) - 2 * (g : Int)
```

This is deliberately a relation, not a quotient/division definition.

Prove:

- genus uniqueness:
  HasCombinatorialGenus M g ->
  HasCombinatorialGenus M h ->
  g = h;
- genus zero iff chi = 2:
  HasCombinatorialGenus M 0 ↔ M.eulerCharacteristic = 2;
- genus one iff chi = 0;
- any witness gives chi <= 2;
- chi is even for any witnessed genus.

Do not prove that every FlowCombinatorialMap has such a genus witness yet.

Do not define genus by truncated Nat division.

## F. Sphere-characteristic certificate

Define a purely combinatorial predicate:

```lean
def HasSphereCharacteristic (M : FlowCombinatorialMap N) : Prop :=
  M.eulerCharacteristic = 2
```

Prove:

```text
HasSphereCharacteristic M
↔
HasCombinatorialGenus M 0.
```

Use the term "sphere characteristic", not "sphere embedding" or "planar",
unless explicitly qualified as combinatorial.

## G. Valid cyclic chi=2 fixture

Add a new positive fixture that is actually a FlowRotationSystem.

Recommended:

- 2 ports per region;
- crossing swaps regions at equal port index;
- local rotation swaps the two ports within each region.

Then:

- total ports D = 4;
- E = 2;
- faceStep should have two 2-cycles;
- F = 2;
- V = 2;
- chi = 2.

Kernel-check the actual face decomposition.

Prove:

- local rotation is cyclic in each region;
- underlying region graph is connected;
- FlowCombinatorialMap certificate exists;
- HasSphereCharacteristic;
- HasCombinatorialGenus 0.

This replaces the weak 2×4 identity fixture as the genus-zero calibration.

## I. Weak chi=2 non-example

Retain the existing 2×4 identity-rotation fixture as a **negative type
calibration**.

Audit/document that its FlowLocalRotation does not satisfy RegionRotationCyclic
for a region with at least two distinct ports.

```text

```

for one region is sufficient.

This demonstrates:

```text

does not imply

```

Do not try to package it as FlowCombinatorialMap.

## J. Component warning

The genus equation chi = 2 - 2g is for the connected wrapper.

Do not generalize it silently to disconnected FlowNetwork data.

For disconnected data, the appropriate characteristic is component-sensitive
and remains later work if needed.

## K. Topological interpretation boundary

State explicitly:

A connected rotation system is standard combinatorial data associated with an
orientable cellular embedding, and the arithmetic equation

    chi = 2 - 2g

is the expected surface formula.

However TRM-025 does **not** formalize or prove the topological realization
theorem.

Therefore:

- HasCombinatorialGenus is an arithmetic certificate;
- HasSphereCharacteristic is chi = 2;
- neither is yet a Lean theorem that the graph embeds in S^2.

Do not name a theorem "planar" merely from chi = 2.
